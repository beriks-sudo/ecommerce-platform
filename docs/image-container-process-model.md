# Image, container and process model

## Image

Объясни image как layered immutable artifact.
image как рецепт а контейнеры в нашем случае это блюдо, если мы меняем блюдо добавляем соль от этого основной рецепт не меняется 
Объясни, почему image не является sleeping container.
image и контейнер это две разные сущности рецепт и блюдо
Приведи пример nginx:alpine как image, из которого можно создать несколько containers.
с помощью image как рецепт можно создать сколько угодно контейнеров блюд


## Container
Объясни container как runtime instance.
это блюдо созданное из image рецепта у него есть начало и конец когда оно приготовится
Опиши lifecycle: create, start, observe, stop, remove, recreate.
создает контейнер, стартует, готовит, останавливается, удаляется, пересоздается
Объясни, почему docker rm не удаляет image.
docker rm удаляет блюдо container но не рецепт image

## Foreground process

Объясни, почему hello-world exits.
он так настроен, выполняет команду отправляет в терминал и отключается
Объясни, почему nginx stays running.
nginx       -> запускает web server -> process слушает port -> container stays running
Упомяни CMD/ENTRYPOINT как место, где image обычно задает default command, без глубокого Dockerfile-разбора.
В рецепте (image) есть строчка: «главное блюдо здесь — борщ». Это и есть CMD / ENTRYPOINT.

Когда ты говоришь «приготовь по этому рецепту» (docker run nginx) и не уточняешь, что именно — кухня смотрит в рецепт и готовит то блюдо, что там записано по
умолчанию. У nginx по умолчанию записано «запусти веб-сервер», поэтому он и запускается сам.
## State and persistence

Объясни writable layer.
это тарелка поверх рецепта
Объясни, почему важные данные требуют volume или bind mount.
Тарелку завтра выбросят (контейнер удалят). Всё, что на ней лежало, — пропадёт вместе с ней.

Поэтому важные продукты (база данных, загруженные пользователями файлы) нельзя оставлять на тарелке. Их кладут в холодильник, который стоит отдельно и не
выбрасывается с тарелкой:

volume — холодильник, которым управляет сам Docker (для базы данных и т.п.).
bind mount — «полка», подключённая прямо из твоего компьютера в контейнер (часто так подключают код проекта).Объясни, почему docker exec не должен быть способом постоянной настройки.
