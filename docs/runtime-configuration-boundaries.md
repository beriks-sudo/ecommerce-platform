# Runtime configuration boundaries

## Что такое build-time
build-time  это этап сборки образа docker build.


## Что такое runtime
runtime — это этап запуска контейнера (`docker run`).
На нём актуальны значения, переданные при запуске через `-e`.

## Для чего используется ARG BUILD_MODE
`ARG BUILD_MODE` — это build-time параметр (метка режима сборки).
Передаётся через `--build-arg BUILD_MODE=local`. Это безопасное, несекретное значение.
`ARG` нельзя использовать для секретов — они могут попасть в build logs и history.

## Почему DB_PASSWORD нельзя класть в ARG, ENV или Dockerfile
Пароль в Dockerfile становится частью истории и metadata образа — его увидит любой,
у кого есть образ. Ещё он начинает восприниматься как default для всех запусков.
Секреты не должны попадать в образ ради удобства.

## Зачем нужен .env.example
`.env.example` — это контракт переменных: он перечисляет, какие переменные нужны,
но без реальных значений. Его безопасно коммитить.
Реальный `.env` с секретами исключён из Git и из Docker context (через `.dockerignore`).

## Как bin/config-diagnostics.sh проверяет переменные без вывода секретов
Скрипт показывает несекретные значения (`APP_ENV`, `DB_HOST`), а про секрет печатает
только факт: `DB_PASSWORD is set` или `DB_PASSWORD is missing`, не выводя само значение.
Так можно проверить, что переменная дошла до контейнера, не раскрывая пароль.
