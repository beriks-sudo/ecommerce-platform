# Readiness vs Start

Старт процесса и готовность сервиса — разные вещи. Ниже — четыре состояния.

- **created** — контейнер создан, но главный процесс ещё не запущен.
- **running** — процесс запущен. Но роль может быть НЕ готова: база ещё
  инициализирует внутреннее состояние, app ещё не подключился к Redis/БД,
  reverse proxy стартовал без рабочего upstream.
- **healthy** — healthcheck (по exit code) подтвердил, что сервис готов
  выполнять свою роль.
- **ready** — сервис реально может принимать работу.

## Почему running ≠ ready

Пример: `app` зависит от `mysql`. Если запускать `app` по факту `running` базы,
он стартует раньше, чем база готова принимать подключения, и падает на первом
же запросе. `running` говорит только о процессе, а не о готовности роли.

Поэтому готовность подтверждает healthcheck, а зависимый сервис ждёт
`depends_on: condition: service_healthy`, а не просто старт соседа.

## Как смотрим состояние

```bash
docker compose ps            # healthy / unhealthy / starting
docker inspect <id> --format '{{json .State.Health}}'   # Status, FailingStreak, Log
```
