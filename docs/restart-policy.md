# Restart policy

Выбрано `restart: unless-stopped` для долгоживущих сервисов (app, mysql, redis).
Они должны работать постоянно, а не завершаться после одной команды. Поэтому
после сбоя их нужно поднимать автоматически; `unless-stopped` делает это, но не
перезапускает, если контейнер остановлен вручную (осознанное решение оператора).

Одноразовым командам (миграция, сидер, разовый скрипт) restart НЕ нужен: они
должны завершиться с кодом 0 после успешного выполнения, иначе политика
перезапуска зациклит нормальное завершение.

## Где помогает
Временный сбой (кратковременная недоступность сети или соседа) — Docker сам
поднимет контейнер. Не перезапускает только если контейнер остановлен вручную.

## Где НЕ помогает (crash loop)
Если причина постоянная — битый ENV, неверная команда старта, отсутствующая
зависимость — restart повторяет то же падение по кругу (crash loop). Это не
лечение: причина в конфигурации/коде, и менять надо её. Диагностика начинается
с logs, exit code и docker inspect, а не с перезапуска.
